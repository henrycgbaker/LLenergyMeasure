Thermal gaps left unset in a study file no longer collapse to zero. `study_execution.experiment_gap_seconds` and `cycle_gap_seconds` are documented as deferring to a machine default, but nothing implemented that default: an unset gap was read as `0`, so experiments ran back-to-back and thermal state bled between measurements for anyone relying on their machine defaults. Both now resolve to the user config's `execution` values (60s between experiments and 300s between cycles unless you change them), while a gap the study declares - including an explicit `0` for no gap - still wins.
