Server-mode window object and multi-level window manager (`harness/window_manager.py`). A first-class `WindowSpec` (`rate`, duration-or-count, ramp exclusion, disclosed attribution policy) defines one measured window; the `WindowManager` drives a rate sweep level by level: run the warmup hook (a seam SM8 fills, no-op today), start the open-loop traffic, exclude the ramp PROSPECTIVELY (the measured span starts after the ramp, never trimmed afterwards), emit an explicit start-window event to open energy measurement, hold the measured span, emit stop-window to close it, then drain every in-flight request to completion for its latency record. Delineation is event-driven (a `WindowEnergySink` seam; the default reuses the existing `MeasurementBracket`), never inferred from timestamps. The two boundary policies stay distinct: the energy denominator counts client-counted tokens received within the measured span, while latency records cover every request issued in the span followed to completion past the close - so a boundary-straddling request appears in latency with its full latency yet contributes only its in-span tokens to the energy denominator. Per-level steady-state validation reuses windowing.py's coefficient-of-variation and stable-through-end machinery (CoV <= 0.05 over 3 consecutive sub-windows); a failing level is stamped invalid-with-reason, never dropped. Adds config knobs under the server namespace: `server.traffic.window_seconds` now defaults to 240s when neither window field is set (it was required), a new `server.traffic.ramp_exclusion_seconds` (default 30s), and a new `server.cooldown_seconds` inter-level pause (default 0). All three join the config identity in both hash families with no new exclusion (`server.traffic.slo` remains the sole declared-hash exclusion).
