Container work now has one home per concern instead of three copies of the same mechanics spread over two layers. Every `docker run` argv is assembled by a single shared core in `llenergymeasure.infra.docker.command`, and the three container shapes - the offline experiment dispatch, the idle-baseline measurement, and the long-lived engine server - are parameterisations of it, with their deliberate divergences stated where each is chosen. The emitted argv is unchanged for all three, byte for byte, verified differentially across 2700 input combinations. Container ownership mechanics move down beside the argv they label: `generate_container_name`, `generate_container_labels`, `require_study_id`, `cleanup_study_containers`, `register_container_cleanup`, `install_sigterm_bridge` and `reap_orphaned_containers` move from `llenergymeasure.study.container_lifecycle` to `llenergymeasure.infra.docker.ownership`; the decision to install the cleanup net for a given run stays with the study runner. The failure-artefact helpers from the same module (`persist_failure_artefacts`, `persist_failure_traceback`, `copy_artefact`) move to `llenergymeasure.study.failure_artefacts`, which is what they were always about. `build_baseline_docker_cmd` becomes `build_baseline_container_argv` in `llenergymeasure.infra.docker.command`, joining the other two shapes. Image pulling is likewise unified: the study runner no longer runs `docker pull` itself and instead calls `llenergymeasure.infra.docker.lifecycle.ensure_images`, which pulls the absent images concurrently behind the same local-inspect guard the single-image `ensure_image` uses; the study keeps only its own reading of each outcome (per-engine failure classification, schema-fingerprint verification, progress rows). There is no compatibility shim: `llenergymeasure.study.container_lifecycle` is gone.
