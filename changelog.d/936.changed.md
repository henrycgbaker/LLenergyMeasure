A `serving` module now owns the online-serving mechanics that every OpenAI-compatible engine shares: server placement, launch (a detached sibling container or a host subprocess), the readiness wait, leak-free shutdown, and the streaming HTTP transport. These previously sat one level below the engines that compose them, mixed in with the container plumbing, and the HTTP transport sat inside the load issuer one level above the server itself. Behaviour is unchanged - the emitted `docker run` argv, the readiness semantics, the streaming token counting and the shutdown escalation are all identical - but import paths move for library users: `ProbeRequest`, `ServerPlacement`, `ServerHandle` and the `Server*Error` types move from `llenergymeasure.infra.server_lifecycle` to `llenergymeasure.serving.types`; the launch/readiness/shutdown functions from `llenergymeasure.infra.server_lifecycle` to `llenergymeasure.serving.lifecycle`; and `HttpxTransport`, `RequestShape`, `CompletionResult` and `require_httpx` from `llenergymeasure.harness.traffic` to `llenergymeasure.serving.transport`. All of them are also re-exported from `llenergymeasure.serving`. `llenergymeasure.harness.Transport` is unchanged, but `HttpxTransport` is no longer re-exported from the `llenergymeasure.harness` facade. There is no compatibility shim: `llenergymeasure.infra.server_lifecycle` is gone.
