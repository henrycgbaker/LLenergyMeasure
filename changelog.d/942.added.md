`execution.gpu_indices` in the user config (`~/.config/llenergymeasure/config.yaml`) restricts llem to a subset of the host's GPUs, machine-wide. Absent (the default) means every visible GPU, so nothing changes unless you set it. When set, llem only ever uses those physical devices - for compute placement AND for energy measurement - on both the container and the process runner path. A study that names no devices inherits the allowed set; a study that names its own must stay inside it, or resolution fails naming both sets. The selection is placement metadata: it is excluded from every config and study-design hash, so restricting llem to a subset of a host's GPUs never changes dedup grouping or study identity.

The process runner path previously had no device scoping at all - `study_execution.gpu_indices` was read only by the container path, so a process-runner study used every visible GPU whatever the config said. It now sets `CUDA_VISIBLE_DEVICES` on the spawned worker and on a launched engine server process, and samples the same physical devices, so compute and energy land on the same hardware. Server-mode energy sampling is fixed alongside: those samplers run in the study process for both placements, so a scoped server was previously measured on device 0 regardless of where it ran. The single-experiment in-process leg cannot enforce a scope without mutating the calling process's environment, so a scoped single experiment does not run there: it routes through the study runner's worker subprocess, which scopes itself before importing torch. Every dispatch path enforces the scope.

`LLEM_DOCKER_GPUS` still wins at `docker run` time, since it is a deliberate per-invocation override and can carry a GPU-/MIG-UUID selector an integer list cannot express. Naming a device outside the resolved scope now logs a warning identifying the escaping indices, or reports the selector as unverifiable when it names no integer devices. The Docker preflight GPU probe uses the run's own `--gpus` selector instead of a hardcoded `--gpus all`, and study preflight warns (never fails) when the scope names a device the host does not appear to have.
