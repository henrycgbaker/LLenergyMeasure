Studies and single experiments now get exactly the same resolution however you submit them. Previously `run_study(StudyConfig(...))` and `run_experiment(...)` bypassed six resolution steps that only the YAML study loader performed, so such a run had no equivalence deduplication, no `study_design_hash` identity, no `dedup_mode` or equivalence-group record, and `study_execution.n_cycles` was silently ignored (one pass regardless of the value). All of it now happens for every route through a single entry point, with no file involved on the programmatic route, so a study file and the equivalent objects resolve to hash-equal studies. Two consequences worth knowing about:

- **Duplicates collapse and cycles are honoured on the programmatic route.** A `StudyConfig` you build in code that declares the same configuration twice now runs it once, `n_cycles` now repeats the experiment list as documented, and the run records its identity hash and equivalence groups like any study. Both routes reject a study that mixes `serving_mode` values with the same error; previously only the YAML route did.
- **Recorded experiment ids can shift for a config carrying an engine-ignored field.** Resolution normalises away fields the engine is known to ignore for a given configuration (for example `temperature` under greedy decoding) and dispatches the normalised form. Studies already behaved this way; now `run_experiment(...)` and `llem run <experiment.yaml>` do too. For such a config the recorded `declared_config_hash`, and therefore the result cell directory and sidecar names, differ from 0.7. The configuration as you wrote it is still recorded in the equivalence-group entry, `llem study plan` lists every normalisation up front, and your own config objects are never modified (the run works on copies). A config with no engine-ignored fields is unaffected.

Two smaller changes come with it. `config.loader.load_experiment_config` now takes only a config file path: the `path` argument is required (it previously defaulted to `None`) and the `cli_overrides` and `user_config_defaults` arguments are gone, since nothing supplied them and layering now has one home. And `llem study plan` no longer re-reads the study file to work out which execution fields it declared.

Resume note: a results directory produced by 0.7 through the programmatic route cannot be resumed under this release. Those manifests carry an empty `study_design_hash` because resolution never ran for them, so resuming reports config drift. That report is correct - the study genuinely resolves differently now - so start a fresh run rather than resuming. Directories written by the YAML route are unaffected.
