A study built programmatically now gets exactly the same resolution as one loaded from YAML. Previously `run_study(StudyConfig(...))` and `run_experiment(...)` bypassed six resolution steps that only the YAML loader performed, so such a study ran with no equivalence deduplication, no `study_design_hash` identity, no `dedup_mode` or equivalence-group record, and `study_execution.n_cycles` silently ignored (one pass regardless of the value). All of it now happens for both routes through a single entry point, with no file involved on the programmatic route, so a study file and the equivalent objects resolve to hash-equal studies. Note the consequences for callers that build a `StudyConfig` in code: duplicate configurations collapse to one run, `n_cycles` is honoured, and each experiment carries the canonical form of its configuration. A study that has not been resolved is now refused at dispatch rather than run without an identity. `llem study plan` no longer re-reads the study file to work out which execution fields it declared, and the unused layering arguments on `config.loader.load_experiment_config` (`cli_overrides`, `user_config_defaults`) are gone.
