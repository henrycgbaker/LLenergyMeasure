Tensor-parallel server mode no longer hangs at the first NCCL collective on hosts that need an NCCL workaround. Host `NCCL_*` environment variables were forwarded into the experiment and baseline containers but not into the engine-server container, so a server-mode run could not receive the setting its offline equivalent got. On a PCIe multi-GPU host whose topology lacks functional peer-to-peer (P2P, e.g. an inter-GPU link reported as `SYS` in `nvidia-smi topo -m`, often because ACS is enabled), a tensor-parallel server therefore hung at NCCL initialisation and never became ready, while the same model measured fine offline. Server containers now inherit the host `NCCL_*` configuration exactly as the other two container shapes do: a host that needs `NCCL_P2P_DISABLE=1` for multi-GPU gets working tensor-parallel server mode by setting it once in the host environment. The variables are emitted as explicit `-e KEY=VALUE` args in sorted key order, so the launch command stays deterministic; a host that exports no `NCCL_*` variable gets an unchanged server command.
