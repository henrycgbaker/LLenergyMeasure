Container safety when more than one study runs on a host. A study with no `study_design_hash` is now refused before it launches any container instead of falling back to a shared `"unknown"` identity: that identity is the label the container cleanup filters on, so one study's exit could stop another concurrently running study's containers mid-measurement (the YAML study path always sets the hash, so this only ever affected programmatically constructed studies). Two studies started in the same second no longer share one results directory - the second takes the next free numbered sibling (`{name}_{timestamp}-2`) instead of writing into the first's directory and overwriting its manifest. Server and baseline containers now carry the same ownership labels the experiment containers do, so the container leak protection (cleanup, orphan reaper) sees them too and a leaked engine server no longer sits on the GPU unnoticed.
