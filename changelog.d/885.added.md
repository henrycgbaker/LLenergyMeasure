A top-level `serving_mode` field on `ExperimentConfig`, a closed `Literal["offline", "server"]` defaulting to `"offline"`. `"offline"` is the only mode with an execution path today; `"server"` is accepted by the config model (online-serving measurement ships with the v0.7.0 server-mode work) but has no execution path yet. It is a conditioning identity axis: it enters the declared, resolved, and observed config-hash families, so an offline config and a server config never deduplicate together. Additive - every existing offline config stays valid and omitting the field is identical to `serving_mode: offline`. Because the field enters the wholesale config dump, the absolute `declared_config_hash` (and `study_design_hash`) of every pre-existing config shifts by one key; this is benign pre-1.0 since dedup is within-study (all configs shift together).
